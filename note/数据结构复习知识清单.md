## 第一章：顺序表与链表

### 1.1 顺序表（Sequential List）

#### 1.1.1 定义与存储结构
- **顺序表**：用一组**地址连续**的存储单元依次存储线性表中的数据元素。
- 逻辑上相邻的元素在物理存储上也相邻。
- 通常用**数组**实现，是线性表的顺序存储结构。
- **随机存取**：可通过下标在 $O(1)$ 时间内访问任意元素。

#### 1.1.2 存储地址计算
- 若每个元素占 $L$ 个存储单元，首地址为 $LOC(a_0)$，则第 $i$ 个元素的地址：
  $$LOC(a_i) = LOC(a_0) + i \times L$$

#### 1.1.3 基本操作与时间复杂度

| 操作 | 时间复杂度 | 说明 |
|------|:---------:|------|
| 按位查找（随机存取） | $O(1)$ | 直接通过下标访问 |
| 按值查找 | $O(n)$ | 需遍历比较 |
| 插入（第 $i$ 位） | $O(n)$ | 需后移 $n-i$ 个元素 |
| 删除（第 $i$ 位） | $O(n)$ | 需前移 $n-i-1$ 个元素 |
| 尾插（有剩余空间） | $O(1)$ | 直接追加 |
| 尾删 | $O(1)$ | 直接删除末尾 |

#### 1.1.4 插入/删除的详细步骤
**插入**：将第 $i$ 到第 $n-1$ 个元素依次后移一位，再将新元素放入第 $i$ 位，表长 $+1$。
- 最好情况：在末尾插入，$O(1)$
- 最坏情况：在表头插入，$O(n)$
- 平均移动次数：$n/2$

**删除**：将第 $i+1$ 到第 $n-1$ 个元素依次前移一位，表长 $-1$。
- 最好情况：删除末尾，$O(1)$
- 最坏情况：删除表头，$O(n)$
- 平均移动次数：$(n-1)/2$

#### 1.1.5 顺序表优缺点
- **优点**：随机存取快 $O(1)$，存储密度高（无指针开销），实现简单。
- **缺点**：插入删除需大量移动元素 $O(n)$；需要预先分配连续空间，可能造成浪费或溢出；扩容代价高。

#### 1.1.6 考点提醒
- 顺序表插入删除的平均移动元素次数计算
- 区分"逻辑位序"和"数组下标"（逻辑位序从 1 开始，数组下标从 0 开始）
- 顺序表是一种**随机存取**的存储结构

### 1.2 链表（Linked List）

#### 1.2.1 单链表

##### 定义与结点结构
```c
typedef struct LNode {
    ElemType data;        // 数据域
    struct LNode *next;   // 指针域
} LNode, *LinkList;
```
- 用**任意**的存储单元存储数据元素（存储地址可以连续也可以不连续）。
- 通过指针链接各结点，逻辑相邻但物理不一定相邻。
- **顺序存取**：只能从头结点开始依次遍历。

##### 头结点 vs 头指针
- **头指针**：指向链表中第一个结点的指针（若无头结点则指向首元结点）。
- **头结点**：在首元结点之前附加的一个结点，数据域通常不存信息（或存表长），指针域指向首元结点。
- 引入头结点的优点：使"空表"和"非空表"的处理统一；在任意位置插入删除操作统一。

##### 基本操作
| 操作 | 时间复杂度 | 说明 |
|------|:---------:|------|
| 按位查找 | $O(n)$ | 需从头遍历 |
| 按值查找 | $O(n)$ | 需遍历比较 |
| 插入结点 | $O(n)$ | 查找前驱需要 $O(n)$，插入本身 $O(1)$ |
| 删除结点 | $O(n)$ | 查找前驱需要 $O(n)$，删除本身 $O(1)$ |
| 头插法建表 | $O(n)$ | 每次插入在头部，逆序 |
| 尾插法建表 | $O(n)$ | 每次插入在尾部，顺序（需维护尾指针） |

##### 头插法 vs 尾插法
- **头插法**：新结点始终插入在头结点之后，建成后链表顺序与输入顺序**相反**。
- **尾插法**：新结点始终插入在表尾，建成后链表顺序与输入顺序**相同**（需维护尾指针 $O(1)$ 插入，否则每次找尾 $O(n^2)$）。

##### 单链表的逆置
- 三指针法（pre, cur, next），时间复杂度 $O(n)$，空间复杂度 $O(1)$。
- 也可用头插法重建，时间复杂度 $O(n)$。

#### 1.2.2 双向链表

##### 结点结构
```c
typedef struct DNode {
    ElemType data;
    struct DNode *prior;  // 前驱指针
    struct DNode *next;   // 后继指针
} DNode, *DLinkList;
```

##### 特点
- 每个结点有两个指针域，可双向遍历。
- 插入/删除时需修改两个指针（prior 和 next），共修改 **4 条链**（插入）/ **2 条链**（删除）。
- 插入删除操作比单链表复杂，但在已知结点指针的情况下可以 $O(1)$ 删除（单链表需找前驱 $O(n)$）。

##### 插入/删除操作（已知结点 p 后插入 s）
```c
// 插入 s 到 p 之后
s->next = p->next;
s->prior = p;
if (p->next) p->next->prior = s;  // 注意非空判断
p->next = s;

// 删除 p 的后继结点 q
p->next = q->next;
if (q->next) q->next->prior = p;
free(q);
```

**注意**：操作顺序很关键，先处理新结点的两个指针，再修改原链表。

#### 1.2.3 循环链表

##### 循环单链表
- 表中最后一个结点的指针域指向**头结点**，整个链表形成一个环。
- 判空条件：`head->next == head`
- 判表尾条件：`p->next == head`
- 常设**尾指针**而非头指针，可 $O(1)$ 访问表头和表尾（`rear->next` 为头结点，`rear->next->next` 为首元结点）。

##### 循环双向链表
- 头结点的 prior 指向尾结点，尾结点的 next 指向头结点。
- 判空条件：`head->prior == head && head->next == head`
- 插入删除无需判断 next/prior 是否为空（永远非空），操作一致性好。

#### 1.2.4 静态链表
- 用**数组**模拟链表，每个元素包含 `data` 和 `next`（存放下一个元素的下标，而非指针）。
- `next = -1` 表示结尾。
- 适用于不支持指针的语言（如早期 BASIC/FORTRAN），或在操作系统中用于文件分配表（FAT）。

---

### 1.3 顺序表 vs 链表 综合对比

| 比较维度 | 顺序表 | 链表 |
|----------|--------|------|
| 存取方式 | 随机存取 $O(1)$ | 顺序存取 $O(n)$ |
| 存储结构 | 连续存储 | 分散存储 |
| 按位查找 | $O(1)$ | $O(n)$ |
| 插入/删除 | $O(n)$（移动元素） | $O(n)$（找前驱）+ $O(1)$（改链） |
| 存储密度 | 高（=1） | 低（<1，因指针开销） |
| 空间分配 | 静态分配，可能溢出或浪费 | 动态分配，较灵活 |
| 缓存友好 | 好（空间局部性） | 差（结点分散） |

#### 考点
- 链表插入/删除语句的书写顺序
- 头插法、尾插法建表的结果顺序
- 双向链表的插入删除操作（四链/二链修改）
- 循环链表的判空条件

## 第二章：栈和队列

### 2.1 栈（Stack）

#### 2.1.1 定义与特点
- **栈**：限定仅在**一端**（栈顶）进行插入和删除操作的线性表。
- **LIFO**（Last In First Out，后进先出）。
- 基本操作：Push（入栈/压栈）、Pop（出栈/弹栈）、GetTop（取栈顶/读栈顶）。

#### 2.1.2 数学性质：卡特兰数
$n$ 个元素的不同出栈序列个数为卡特兰数：
$$C_n = \frac{1}{n+1}\binom{2n}{n}$$

- $n=3$ 时，出栈序列有 5 种
- $n=4$ 时，出栈序列有 14 种

#### 2.1.3 顺序栈

```c
typedef struct {
    ElemType data[MAXSIZE];
    int top;   // 栈顶指针
} SqStack;
```

- **栈空条件**：`top == -1`（初始值）
- **栈满条件**：`top == MAXSIZE - 1`
- **入栈**：`data[++top] = x;`（先加后放）
- **出栈**：`x = data[top--];`（先取后减）

**注**：若 top 指向下一个可用位置（初始 top=0），则空/满条件和操作顺序不同。关键是统一约定。

##### 共享栈（两栈共享空间）
- 两个栈共享同一段数组空间，一个从低地址向高地址增长，一个从高地址向低地址增长。
- **栈满条件**：`top1 + 1 == top2`（两栈顶相遇）
- 优点：更有效地利用空间，减少溢出可能。

#### 2.1.4 链栈

```c
typedef struct StackNode {
    ElemType data;
    struct StackNode *next;
} StackNode;

// 链栈没有头结点，top 直接指向栈顶结点
// 入栈 = 头插；出栈 = 删除首结点
```

- 链栈的栈顶在**链表头部**（头插法入栈，$O(1)$）。
- 不会出现栈满（除非内存耗尽）。
- 所有操作 $O(1)$。

#### 2.1.5 栈的应用
1. **括号匹配**：遇到左括号入栈，右括号出栈匹配。
2. **表达式求值**：中缀表达式 → 后缀表达式（逆波兰式），再用栈求值。
3. **递归**：函数调用栈（保存返回地址、局部变量等）。
4. **迷宫问题/DFS**：深搜的回溯。
5. **进制转换**：除基取余，逆序输出。

#### 2.1.6 表达式转换（重点）

##### 中缀转后缀（算法）
1. 操作数直接输出。
2. 运算符：若优先级**高于**栈顶运算符（或栈空），入栈；否则，不断弹栈输出直到可入栈。
3. 左括号 `(` 直接入栈；右括号 `)` 弹栈输出直到遇到 `(`（括号不输出）。
4. 扫描完后，依次弹栈输出所有剩余运算符。

##### 中缀转前缀
- 从右向左扫描中缀表达式，或用后缀再反转得到前缀。

##### 后缀表达式求值
- 操作数入栈；遇到运算符则弹出两个操作数，计算后结果入栈。

#### 2.1.7 考点
- 给定入栈序列判断可能的出栈序列
- $n$ 个元素的出栈序列个数（卡特兰数）
- 链栈的栈顶位置（链表头部）
- 共享栈的判满条件
- 中缀/后缀/前缀表达式互转
- 用栈模拟特定序列：如判断 "以 $i,j,k$ 开头的出栈序列能否由入栈序列 $1,2,3,\ldots$ 得到"

### 2.2 队列（Queue）

#### 2.2.1 定义与特点
- **队列**：限定在**一端**（队尾）插入、**另一端**（队头）删除的线性表。
- **FIFO**（First In First Out，先进先出）。
- 基本操作：EnQueue（入队）、DeQueue（出队）、GetHead（取队头）。

#### 2.2.2 顺序队列（循环队列）

##### 为什么要循环
- 普通顺序队列：多次入队出队后，`front` 前移导致前面空间无法利用（**假溢出**）。
- 循环队列：将存储空间逻辑上看作环形，`rear` 和 `front` 循环移动。

##### 实现细节
```c
typedef struct {
    ElemType data[MAXSIZE];
    int front;   // 队头指针
    int rear;    // 队尾指针
} SqQueue;
```

##### 队空/队满的判断（三种常用方式）

| 方式 | 队空条件 | 队满条件 | 说明 |
|------|----------|----------|------|
| 方式一 | `front == rear` | `(rear+1) % MAXSIZE == front` | **牺牲一个存储单元**，最常用 |
| 方式二 | `front == rear` | `(rear+1) % MAXSIZE == front` + 设 size | 增加 size 变量记录元素个数 |
| 方式三 | `front == rear` + tag=0 | `front == rear` + tag=1 | 增加 tag 变量标记最后一次操作是入队还是出队 |

##### 基本操作（方式一，牺牲一个单元）
```c
// 入队
rear = (rear + 1) % MAXSIZE;
data[rear] = x;

// 出队
front = (front + 1) % MAXSIZE;
x = data[front];
```

- **队列长度**：`(rear - front + MAXSIZE) % MAXSIZE`
- 队头元素在 `(front + 1) % MAXSIZE` 位置（若 front 指向队头前一个位置）

**注意**：front 和 rear 初始值设置有两种约定：
- 约定一：`front = rear = 0`，front 指向队头元素，rear 指向队尾元素的下一个位置。此时入队先放后移，出队先取后移。
- 约定二：`front = rear = -1` 或其他。不同教材约定不同，关键是理解逻辑。

#### 2.2.3 链队列

```c
typedef struct QNode {
    ElemType data;
    struct QNode *next;
} QNode;

typedef struct {
    QNode *front;   // 队头指针
    QNode *rear;    // 队尾指针
} LinkQueue;
```

- 通常带头结点：`front` 指向头结点，`rear` 指向尾结点。
- 空队条件：`front == rear`（都指向头结点）。
- 入队：在 rear 后插入，更新 rear。
- 出队：删除 front->next 结点，若删除的是最后一个结点，需将 rear 指回头结点。
- 所有操作 $O(1)$。

#### 2.2.4 双端队列
- **双端队列**：两端都可以进行插入和删除操作。
- **输入受限双端队列**：一端允许插入和删除，另一端只允许删除。
- **输出受限双端队列**：一端允许插入和删除，另一端只允许插入。
- 考点：判断某序列能否由输入/输出受限的双端队列得到。

#### 2.2.5 队列的应用
1. **层次遍历**（二叉树层序遍历、图的 BFS）
2. **操作系统**：进程调度（就绪队列）、打印缓冲队列（SPOOLing）
3. **缓冲区**：键盘输入缓冲区
4. **消息队列**：生产者-消费者模型
5. **迷宫最短路径**：BFS 求无权图最短路径
6. **页面置换算法（FIFO）**

#### 2.2.6 考点
- 循环队列的判空/判满条件
- 队列元素个数计算
- 入队/出队后 front 和 rear 的变化
- 链队出队时特殊情况的处理（只剩一个结点）
- 双端队列的输出序列合法性判断

---

### 2.3 栈和队列的对比

| 比较项 | 栈 | 队列 |
|--------|----|------|
| 操作端 | 同一端（栈顶） | 两端（队头删，队尾插） |
| 特点 | LIFO（后进先出） | FIFO（先进先出） |
| 典型应用 | 递归、括号匹配、表达式求值 | 层次遍历、BFS、进程调度 |
| 顺序结构 | 顺序栈 | 循环队列 |
| 链式结构 | 链栈（栈顶在表头） | 链队（需两个指针） |

## 第三章：字符串、多维数组、矩阵的压缩存储

### 3.1 字符串（String）

#### 3.1.1 定义与基本概念
- **串**：由零个或多个字符组成的有限序列。记为 $S = "a_1a_2\ldots a_n"$。
- **空串**：长度为 0 的串（`""`），与空格串（由空格字符组成）不同。
- **子串**：串中任意连续字符组成的子序列。
- **主串**：包含子串的串。
- **串的长度**：串中字符的数目。
- **串相等**：长度相等且对应位置字符相等。

#### 3.1.2 存储结构

##### 定长顺序存储
```c
typedef struct {
    char ch[MAXSIZE];
    int length;
} SString;
```

##### 堆分配存储
```c
typedef struct {
    char *ch;     // 动态分配
    int length;
} HString;
```

##### 块链存储
- 用链表存储字符串，每个结点可存放一个或多个字符。
- **存储密度** = 串值所占字节数 / 结点结构所占字节数。结点中字符位越多，存储密度越高。

#### 3.1.3 模式匹配算法

##### BF 算法（Brute Force，朴素匹配）
- 主串指针 i 和模式串指针 j 从头部开始匹配；失配时 i 回溯到 `i - j + 2`，j 回溯到 1。
- 时间复杂度：
  - 最好：$O(n+m)$（每次第一个字符就不匹配）
  - 最坏：$O(n \times m)$（如主串 `"aaaaaaaaab"`，模式串 `"aaab"`）
  - 平均：$O(n+m)$（一般情况）

##### KMP 算法
- **核心思想**：利用已匹配部分的信息避免主串指针 i 回溯。
- next 数组：当模式串第 j 个字符与主串失配时，模式串应跳到的位置。
- 时间复杂度：$O(n+m)$

**next 数组的定义**（下标从 1 开始的版本）：
$$next[j] = \begin{cases}
0 & j = 1 \\
\max\{k \mid 1 < k < j \text{ 且 } p_1\ldots p_{k-1} = p_{j-k+1}\ldots p_{j-1}\} & \text{集合非空} \\
1 & \text{其他情况}
\end{cases}$$

直观理解：next[j] = "前 j-1 个字符的最长相等前后缀长度 + 1"。

**nextval 数组（优化版）**：若 $p_j = p_{next[j]}$，则继续取 $nextval[j] = nextval[next[j]]$，避免连续的无效比较。

##### KMP 的手算技巧
1. 模式串下标从 1 开始，`next[1] = 0`，`next[2] = 1`。
2. 对于 `next[j]`（j≥3）：看前 j-1 个字符，找最大 k 使得前缀 = 后缀，`next[j] = k + 1`。
3. 若不存在这样的 k，`next[j] = 1`。
4. nextval[j]：若 `p[j] ≠ p[next[j]]` 则 `nextval[j] = next[j]`；否则 `nextval[j] = nextval[next[j]]`。

#### 3.1.4 考点
- KMP 算法手工计算 next 数组和 nextval 数组
- BF 算法的匹配过程和回溯
- 子串计数（长度为 n 的串有多少个子串：$n(n+1)/2 + 1$，含空串）
- 串的存储方式

### 3.2 多维数组

#### 3.2.1 数组的定义与特点
- 数组是 $n$ 个相同类型数据元素构成的有限序列。
- 数组是多维的，本质上是一个**线性表的推广**。
- 数组一旦定义，维数和维界不再改变，只有**存取**和**修改**操作。
- 数组是一种**随机存取**结构。

#### 3.2.2 数组的存储结构
- 用**一维存储空间**存储多维数组，需要约定元素排列顺序。

##### 行优先存储（Row Major Order，以行为主序）
- 最常用（C/C++、Java、Python 均用行优先）。
- 对于 $m \times n$ 的二维数组 $A[m][n]$，元素 $A[i][j]$ 的地址：
  $$LOC(A[i][j]) = LOC(A[0][0]) + (i \times n + j) \times L$$
  其中 $L$ 为每个元素所占字节数。

##### 列优先存储（Column Major Order，以列为主序）
- MATLAB、Fortran 使用列优先。
- 元素 $A[i][j]$ 的地址：
  $$LOC(A[i][j]) = LOC(A[0][0]) + (j \times m + i) \times L$$

##### n 维数组的行优先地址公式
对于 $n$ 维数组 $A[b_1][b_2]\ldots[b_n]$（$b_i$ 为第 i 维的大小），元素 $A[j_1][j_2]\ldots[j_n]$ 的地址：
$$LOC = LOC(A[0\ldots0]) + (j_1 \times b_2 \times b_3 \times \ldots \times b_n + j_2 \times b_3 \times \ldots \times b_n + \ldots + j_{n-1} \times b_n + j_n) \times L$$

#### 3.2.3 考点
- 给定数组下标和存储方式，计算元素的存储地址
- 行优先和列优先的地址公式区分

---

### 3.3 矩阵的压缩存储

#### 3.3.1 压缩存储的概念
- 为多个值相同的元素只分配**一个**存储空间，对零元素不分配空间。
- 目的是节省存储空间。

#### 3.3.2 对称矩阵

##### 定义
$n$ 阶方阵 $A$ 满足 $a_{ij} = a_{ji}$（$0 \le i, j < n$）。

##### 存储方式
- 只存储**上三角**或**下三角**（含主对角线），共 $n(n+1)/2$ 个元素。
- 存入一维数组 $B[0\ldots n(n+1)/2 - 1]$。

##### 下三角存储（行优先）
$$k = \frac{i(i-1)}{2} + j - 1 \quad (\text{当 } i \ge j)$$
若 $i < j$，则用 $a_{ji}$ 对称查找（交换 i 和 j）。

（此处 $i,j$ 下标从 1 开始）
- 第 1 行：1 个元素
- 第 2 行：2 个元素
- 第 i 行前有 $\frac{i(i-1)}{2}$ 个元素

##### 上三角存储（列优先）
$$k = \frac{j(j-1)}{2} + i - 1 \quad (\text{当 } j \ge i)$$

#### 3.3.3 三角矩阵

##### 下三角矩阵
- 下三角（含主对角线）元素不全是 0/同一常量，上三角（不含主对角线）**全为同一常量** $c$。
- 存储下三角 $n(n+1)/2$ 个元素 + 1 个常量 $c$（共 $n(n+1)/2 + 1$ 个单元）。
- 存取公式：
  $$k = \begin{cases}
  \frac{i(i-1)}{2} + j - 1 & i \ge j \\
  \frac{n(n+1)}{2} & i < j \text{（常量 c）}
  \end{cases}$$

##### 上三角矩阵
- 上三角（含主对角线）存储，下三角全为常量 $c$。
- 存取公式（行优先）：
  $$k = (i-1)(2n-i+2)/2 + (j-i) \quad (\text{当 } i \le j)$$

#### 3.3.4 对角矩阵（带状矩阵）

##### 三对角矩阵
- 所有非零元素集中在以主对角线为中心的**三条对角线**上。
- $|i-j| \le 1$ 时 $a_{ij} \neq 0$，其余为 0。
- 非零元素个数：$3n - 2$（n 阶）。
- 行优先存储时元素 $a_{ij}$ 的地址：
  $$k = 2i + j - 3 \quad (\text{当 } |i-j| \le 1)$$
  即第 i 行有 3 个元素，前 i 行共有 $3i - 2$ 个元素。

#### 3.3.5 稀疏矩阵

##### 定义
非零元素个数远少于矩阵元素总数（一般非零元素占比 $< 5\%$）的矩阵。

##### 三元组表示法（顺序存储）
```c
typedef struct {
    int row;   // 行号
    int col;   // 列号
    ElemType value;  // 元素值
} Triple;

typedef struct {
    Triple data[MAXSIZE];  // 三元组表，按行优先排列
    int rows, cols, num;   // 行数、列数、非零元个数
} TSMatrix;
```

##### 十字链表表示法（链式存储）
```c
typedef struct OLNode {
    int row, col;
    ElemType value;
    struct OLNode *right;  // 指向同行下一个非零元
    struct OLNode *down;   // 指向同列下一个非零元
} OLNode;
```
- 分别设**行头指针数组**和**列头指针数组**。
- 适合做矩阵加法、乘法等动态操作（非零元位置变化频繁）。

##### 稀疏矩阵的转置
- **简单转置**：按列扫描三元组表 $O(cols \times num)$，效率低。
- **快速转置**：先统计每列非零元个数，计算每列在新三元组表中的起始位置，一次扫描完成 $O(num + cols)$。

#### 3.3.6 考点
- 对称矩阵压缩存储的下标计算公式
- 三角矩阵中常量 c 的存储位置
- 压缩矩阵地址计算：给定 $a_{ij}$ 求在一维数组中的下标 $k$
- 稀疏矩阵的三元组和十字链表表示

## 第四章：树与二叉树

### 4.1 树的基本概念

#### 4.1.1 定义
- **树**：$n (n \ge 0)$ 个结点的有限集。$n=0$ 时称空树。
- 非空树满足：
  1. 有且仅有一个**根结点**。
  2. 当 $n > 1$ 时，其余结点可分为 $m$ 个互不相交的有限集，每个集合本身又是一棵树，称为根的**子树**。
- 树是一种**递归**定义的数据结构，也是一种**分层**结构。

#### 4.1.2 基本术语

| 术语 | 定义 |
|------|------|
| **结点的度** | 该结点的子结点个数 |
| **树的度** | 树中所有结点的最大度数 |
| **叶子结点/终端结点** | 度为 0 的结点 |
| **分支结点/非终端结点** | 度 > 0 的结点 |
| **孩子/子结点** | 某结点的子树的根结点 |
| **双亲/父结点** | 某结点的上层结点 |
| **兄弟** | 同一双亲的孩子之间互称兄弟 |
| **堂兄弟** | 双亲在同一层的结点 |
| **结点的层次** | 从根开始，根为第 1 层，根的孩子为第 2 层…… |
| **树的深度/高度** | 树中结点的最大层次 |
| **路径** | 从上到下（或从下到上）经过的结点序列 |
| **路径长度** | 路径上经过的边的数目 |
| **有序树** | 子树从左至右有次序，不可互换 |
| **无序树** | 子树之间无次序，可互换 |
| **森林** | $m (m \ge 0)$ 棵互不相交的树的集合 |

#### 4.1.3 树的性质
1. 树中结点数 = 所有结点的度数之和 + 1（每个非根结点恰好对应一条边）。
2. 度为 $m$ 的树中，第 $i$ 层上至多有 $m^{i-1}$ 个结点（$i \ge 1$）。
3. 高度为 $h$ 的 $m$ 叉树至多有 $\frac{m^h-1}{m-1}$ 个结点。
4. 具有 $n$ 个结点的 $m$ 叉树的最小高度为 $\lceil \log_m(n(m-1)+1) \rceil$。

#### 4.1.4 树的存储结构

##### 双亲表示法
- 用数组存储，每个结点含 `data` 和 `parent`（指向双亲在数组中的下标）。
- 根结点的 parent = -1。
- 特点：找双亲 $O(1)$，找孩子需遍历 $O(n)$。

##### 孩子表示法
- 每个结点用一个链表存储所有孩子。
- 也可用**孩子链表表示法**（数组 + 链表）。

##### 孩子兄弟表示法（二叉树表示法 / 左孩子右兄弟）
```c
typedef struct CSNode {
    ElemType data;
    struct CSNode *firstChild;   // 指向第一个孩子
    struct CSNode *nextSibling;  // 指向下一个兄弟
} CSNode;
```
- **最常用**的树存储方式。
- 可以方便地实现树 ↔ 二叉树转换。

---

### 4.2 二叉树

#### 4.2.1 定义
- **二叉树**是 $n (n \ge 0)$ 个结点的有限集，或为空树，或由一个根结点和两棵互不相交的、分别称为**左子树**和**右子树**的二叉树组成。
- 二叉树与树的区别：二叉树有**左右之分**，即使只有一棵子树也需区分左右。度为 2 的有序树不等同于二叉树（有序树区分左右的前提是有多个孩子）。

#### 4.2.2 特殊二叉树

##### 满二叉树
- 高度为 $h$，含有 $2^h - 1$ 个结点的二叉树。
- 每层都"满"：第 $i$ 层有 $2^{i-1}$ 个结点。
- 所有叶子结点都在同一层（最底层）。
- 编号：从上到下、从左到右，与完全二叉树的一致。

##### 完全二叉树
- 高度为 $h$，有 $n$ 个结点的二叉树，当且仅当其每个结点都与高度为 $h$ 的满二叉树中编号 $1 \sim n$ 的结点**一一对应**。
- 简单理解：对满二叉树进行编号，删掉若干编号最大的结点（从右向左连续删除）。
- 性质：叶子结点只可能在**最后两层**出现；若某个结点只有左孩子没有右孩子，则按层序编号在其后的所有结点都是叶子。
- 完全二叉树适合用**顺序存储**。

##### 二叉排序树（BST）
- 左子树所有结点的值 < 根结点的值 < 右子树所有结点的值。
- 左右子树也是二叉排序树。
- 中序遍历得到递增序列。

##### 平衡二叉树（AVL）
- 任意结点的左右子树高度差的绝对值不超过 1。
- 查找效率高 $O(\log n)$。

#### 4.2.3 二叉树的性质（非常重要）

1. **叶子结点与度为 2 的结点关系**：$n_0 = n_2 + 1$
   - 推导：$n = n_0 + n_1 + n_2$，$n = B + 1 = n_1 + 2n_2 + 1$，联立得 $n_0 = n_2 + 1$。

2. **第 $i$ 层最多结点数**：$2^{i-1}$ 个（$i \ge 1$）。

3. **高度为 $h$ 的二叉树最多结点数**：$2^h - 1$ 个（满二叉树）。

4. **$n$ 个结点的完全二叉树**：
   - 深度：$\lfloor \log_2 n \rfloor + 1$（或 $\lceil \log_2(n+1) \rceil$）
   - 编号为 $i$ 的结点：
     - 双亲：$\lfloor i/2 \rfloor$（$i > 1$）
     - 左孩子：$2i$（若 $2i \le n$）
     - 右孩子：$2i + 1$（若 $2i+1 \le n$）
     - 若 $i$ 为偶数，是双亲的左孩子；若 $i$ 为奇数（且 $i>1$），是双亲的右孩子
   - $i \le \lfloor n/2 \rfloor$ 的结点是分支结点，$i > \lfloor n/2 \rfloor$ 是叶子结点

5. **具有 $n$ 个结点的完全二叉树，叶子结点数**：
   - 若 $n$ 为偶数：$n_0 = n/2$
   - 若 $n$ 为奇数：$n_0 = (n+1)/2$
   - 统一起见：$n_0 = \lceil n/2 \rceil$

6. **$n$ 个结点的二叉树形态数**：卡特兰数 $C_n = \frac{1}{n+1}\binom{2n}{n}$

#### 4.2.4 二叉树的存储结构

##### 顺序存储
- 用一维数组，按完全二叉树的编号方式存储。
- 对于一般的二叉树：需添加"空结点"补齐成完全二叉树，编号为 $i$ 的结点存储在 `data[i]`。
- **缺点**：对于单支树等形态，空间利用率极低。一般仅用于完全二叉树。

##### 链式存储（二叉链表）
```c
typedef struct BiTNode {
    ElemType data;
    struct BiTNode *lchild, *rchild;
} BiTNode, *BiTree;
```
- $n$ 个结点的二叉链表共有 $n+1$ 个**空链域**（$2n$ 个指针域，$n-1$ 条边，故 $2n - (n-1) = n+1$）。
- 可以增设 parent 指针形成**三叉链表**。

#### 4.2.5 二叉树的遍历（核心考点）

##### 深度优先遍历（递归定义）

| 遍历方式 | 顺序 | 特点 |
|----------|------|------|
| **先序遍历** | 根 → 左子树 → 右子树 | 第一个访问的是根结点 |
| **中序遍历** | 左子树 → 根 → 右子树 | BST 中序遍历得到升序序列 |
| **后序遍历** | 左子树 → 右子树 → 根 | 最后一个访问的是根结点 |

##### 遍历序列的性质
- 已知**先序 + 中序**，或**后序 + 中序**，或**层序 + 中序**，可**唯一确定**一棵二叉树。
- 已知**先序 + 后序**，**不能**唯一确定一棵二叉树（但可唯一确定真二叉树，即每个结点度数为 0 或 2）。

**手工重建二叉树的方法**（以先序+中序为例）：
1. 先序第一个为根结点。
2. 在中序中找到根结点，左边为左子树的中序序列，右边为右子树的中序序列。
3. 根据左子树中序长度，在先序中确定左子树的先序序列。
4. 递归地对左右子树执行相同操作。

##### 非递归遍历
- 借助**栈**模拟递归过程。
- 先序非递归：弹栈访问 → 右孩子入栈 → 左孩子入栈（或反之，取决于遍历顺序）
- 中序非递归：沿左链走到底并入栈 → 弹栈访问 → 转向右孩子 → 重复
- 后序非递归：较复杂，需标记访问状态（或双栈法）。

##### 层次遍历（广度优先）
- 借助**队列**：
  1. 根结点入队。
  2. 队头出队并访问，将其左、右孩子依次入队。
  3. 重复步骤 2 直到队空。

##### 遍历的应用
- 求树的深度（后序遍历）
- 求叶子结点个数（任意遍历，判断度为 0）
- 复制二叉树（先序遍历）
- 判断两棵树是否相等
- 查找值为 x 的结点

#### 4.2.6 线索二叉树

##### 基本概念
- **线索**：利用二叉链表中 $n+1$ 个空链域，存放指向遍历序列中**前驱**和**后继**的指针。
- **线索化**：对二叉树按某种遍历次序使其变为线索二叉树的过程。

##### 结点结构
```c
typedef struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;   // 0-指向孩子，1-指向前驱/后继（线索）
} ThreadNode;
```

##### 三种线索二叉树
- 先序线索二叉树
- 中序线索二叉树（**最常用**）：可以方便找到中序前驱和后继
- 后序线索二叉树

##### 中序线索二叉树中找前驱/后继
- **找后继**：若 `rtag == 1`，则 `rchild` 即为后继；若 `rtag == 0`，则后继为右子树的**中序第一个结点**（沿左链走到最左下角）。
- **找前驱**：若 `ltag == 1`，则 `lchild` 即为前驱；若 `ltag == 0`，则前驱为左子树的**中序最后一个结点**（沿右链走到最右下角）。

##### 考点
- 手工画线索二叉树（用虚线箭头标出前驱/后继）
- 线索二叉树的结点结构（ltag/rtag 的含义）
- $n$ 个结点的二叉链表有 $n+1$ 个空链域可用于线索

### 4.3 树、森林与二叉树的转换

#### 4.3.1 树 → 二叉树（左孩子右兄弟）
**转换规则**：
1. **加线**：在兄弟之间加一条连线。
2. **抹线**：对每个结点，只保留与**第一个孩子**的连线，抹去与其他孩子的连线。
3. **旋转**：将保留的连线调整为左子树（第一个孩子），兄弟连线调整为右子树。

结果：树的先根遍历 = 二叉树的先序遍历；树的后根遍历 = 二叉树的中序遍历。

#### 4.3.2 森林 → 二叉树
1. 将森林中每棵树分别转换为二叉树。
2. 从第一棵二叉树开始，依次将后一棵二叉树的根作为前一棵二叉树根的**右孩子**。

结果：森林的先序遍历 = 二叉树的先序遍历；森林的中序遍历 = 二叉树的中序遍历。

#### 4.3.3 二叉树 → 树/森林
**逆操作**：二叉树的根及左子树为其对应的第一棵树的二叉表示，右子树为剩余森林的二叉表示。递归处理。

#### 4.3.4 树的遍历

| 遍历方式 | 顺序 | 对应二叉树的遍历 |
|----------|------|:----------------:|
| **先根遍历** | 访问根 → 依次先根遍历每棵子树 | 先序遍历 |
| **后根遍历** | 依次后根遍历每棵子树 → 访问根 | 中序遍历 |
| 层次遍历 | 从上到下、从左到右 | — |

#### 4.3.5 森林的遍历

| 遍历方式 | 顺序 | 对应二叉树的遍历 |
|----------|------|:----------------:|
| **先序遍历森林** | 访问第一棵的根 → 先序遍历第一棵的子树森林 → 先序遍历剩余森林 | 先序遍历 |
| **中序遍历森林** | 中序遍历第一棵的子树森林 → 访问第一棵的根 → 中序遍历剩余森林 | 中序遍历 |

#### 4.3.6 考点
- 树/森林 → 二叉树的手工转换
- 树和森林的遍历序列与对应二叉树遍历序列的对应关系
- 树的遍历名称：先根/后根（与二叉树的先序/中序对应）

### 4.4 哈夫曼树及其应用

#### 4.4.1 基本概念

##### 带权路径长度
- **结点的权**：给结点赋予的有某种意义的数值。
- **结点的带权路径长度**：从根到该结点的路径长度 × 该结点的权。
- **树的带权路径长度（WPL）**：所有**叶子结点**的带权路径长度之和。
  $$WPL = \sum_{i=1}^{n} w_i \times l_i$$
  其中 $w_i$ 为叶子权值，$l_i$ 为叶子到根的路径长度。

##### 哈夫曼树（最优二叉树）
- 在含有 $n$ 个带权叶子结点的二叉树中，**WPL 最小**的二叉树称为哈夫曼树。

#### 4.4.2 哈夫曼算法（构造哈夫曼树）

1. 将 $n$ 个结点分别作为**只含一个结点**的二叉树，构成森林 $F$。
2. 从 $F$ 中选出**两个根结点权值最小**的树作为左右子树，构造一棵新二叉树，新根的权值 = 左右子树根权值之和。
3. 从 $F$ 中删除选出的两棵树，加入新构造的树。
4. 重复步骤 2-3，直到 $F$ 中只剩一棵树（即哈夫曼树）。

##### 特点
- 初始结点最终都成为**叶子结点**。
- 权值越大的叶子离根越近。
- 构造过程中共合并 $n-1$ 次，产生 $n-1$ 个新结点，因此哈夫曼树共有 $2n-1$ 个结点。
- 没有度为 1 的结点（$n_1 = 0$），只有度为 0 和度为 2 的结点。

#### 4.4.3 哈夫曼编码

##### 概念
- **前缀编码**：任何一个字符的编码都不是另一个字符编码的前缀。保证解码无歧义。
- **哈夫曼编码**：利用哈夫曼树构造的最优前缀编码。

##### 编码方法
1. 将字符出现的频率（或次数）作为权值，构造哈夫曼树。
2. 左分支标记为 0，右分支标记为 1（或反过来，但需一致）。
3. 从根到叶子的路径上标记的序列即为该字符的哈夫曼编码。

##### 性质
- 哈夫曼编码是**最优前缀编码**（平均编码长度最短）。
- 哈夫曼编码**不唯一**：
  - 当左右子树交换时（0/1 的规定不同），编码不同。
  - 当存在相同权值的结点作不同的选择时（两个最小权值有多个备选），树结构不同。
  - 但不同哈夫曼编码的**平均编码长度相同**（WPL 相同）。

#### 4.4.4 哈夫曼 n 叉树
- 对于 $k$ 叉哈夫曼树，若初始结点数为 $n$，需要满足 $(n-1) \bmod (k-1) = 0$（每次合并减少 $k-1$ 棵树）。
- 若不满足，需补充权值为 $0$ 的虚结点（使得每次都能取 $k$ 个合并）。

#### 4.4.5 并查集（与哈夫曼树同属树的应用）
- 支持 Union（合并）和 Find（查找）操作。
- 存储采用**双亲表示法**，`parent[i]` 为 $i$ 的双亲，根结点的 parent 为 -1（或自身）。
- 优化：
  - **按秩合并**（Union by Rank）：矮树合并到高树。
  - **路径压缩**（Path Compression）：查找时把路径上所有结点直接连到根。
  - 两种优化同时使用时，操作的时间复杂度接近 $O(\alpha(n))$（反阿克曼函数，可视为常数）。

#### 4.4.6 考点
- 给定权值集合，手工构造哈夫曼树，计算 WPL
- 给定字符频率，构造哈夫曼编码，计算带权路径长度 WPL
- 哈夫曼树的结点数（$2n-1$，其中 $n$ 为叶子数）
- 哈夫曼树的结点度数特点（$n_0 = n_2 + 1$，$n_1 = 0$，故 $n_0 = (n+1)/2$ 即叶子数 = 总结点数的一半上取整）
- 哈夫曼编码是前缀码，但不一定是"最小"编码长度（取决于是否以频率为权）
- $k$ 叉哈夫曼树的虚结点补充
